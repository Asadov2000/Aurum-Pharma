# Конструктор ролей: проверка изменений

Используется согласованный улучшенный вариант действующего конструктора:
данные роли, разделы функций и каталог. На узком экране данные и функции
разделены вкладками; проверка публикации остаётся вне прокручиваемого каталога.

«Изменения» показывает разницу между открытой версией и текущим выбором:
добавленные функции и снятые функции. Возврат исходного выбора убирает отметку.
Поиск и выбор раздела применяются ко всем фильтрам. Групповая кнопка меняет
только показанные функции, сохраняя выбор в других разделах.

Сводка использует реальное число активных назначений роли. Это не число
уникальных сотрудников: один сотрудник может иметь несколько назначений.
Окно публикации перечисляет добавленные и убранные функции и изменения
названия и описания. Версия и число назначений соответствуют снимку роли,
открытому для редактирования; сервер повторно проверяет `expected_version`.

Системные, защищённые и глобальные роли не редактируются. Роли с неизвестными
или скрытыми правами остаются заблокированными. Перед отправкой уже открытого
подтверждения повторно проверяются каталог, доступность роли и все выбранные
права. Изменение метаданных безопасности выбранных функций требует новой
проверки; недоступные права не удаляются из подтверждённого состава молча.
При ошибке списка или потере права изменения черновик остаётся в окне,
а публикация блокируется.

В отличие от сокращённого макета сохранены шаблоны создания, фильтр всех
функций повышенного риска, подтверждение критичных добавлений и существующая
история версий. Точки выбираются отдельно при назначении роли сотруднику.
Backend, API и автоматические зависимости функций не менялись.

Проверки: `RoleBuilder.test.tsx`, `RolesPage.test.tsx`, `RouteAccess.test.tsx`,
`labels.test.ts`, реальные сценарии `owner-role-builder.spec.ts` и
адаптивность конструктора в `interface-layout.spec.ts`; полный CI gate перед
включением в `main`.
