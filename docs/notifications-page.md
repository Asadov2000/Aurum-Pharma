# Личные уведомления

Выбран вариант 1: входящие слева, настройки получения справа. На узком экране
панели идут последовательно. Обе панели остаются смонтированными: чтение сообщений
и обновление списка не сбрасывают несохранённые настройки.

## Поведение

- Список использует существующий API текущего пользователя, фильтры непрочитанного
  и важности. Страница содержит до 100 сообщений; кнопка «Далее» появляется при
  полной странице. API не сообщает общее число: счётчик относится к текущей
  подборке, на последней полной странице возможен переход на пустую следующую.
- «Отметить все» сохраняет прежнее значение: все сообщения текущего пользователя,
  включая скрытые фильтрами. Действие прямо поясняется рядом с кнопкой.
- Ошибки чтения видны; ошибочный и временный список предыдущего фильтра/страницы
  скрыт до успешного ответа. Доступны повтор и обновление списка.
- Время показывается для пилота в Asia/Dushanbe (UTC+5).
- Настройки относятся к своему аккаунту. Обязательный вход с нового устройства
  остаётся включённым с каналом in_app; SMS и Telegram не предлагаются как готовые.
- Неизвестные существующие настройки сохраняются при отправке. Изменения формы
  сохраняются при фоновом обновлении и ошибке; успешное сохранение применяет
  ответ сервера. Для включённого известного события нужен доступный канал.

## Границы

Backend, RLS и способы входа не менялись. Существующие события license/trial/invoice
в реальном каталоге сохранены: их удаление относится к отдельной синхронизации
домена уведомлений с отказом от подписок. Макет эти исторические события не показывал.

## Проверки

Vitest: совместные панели, чтение одного/всех, ошибки/повтор, фильтры и страницы,
сохранение обязательных каналов и черновика при обновлении.
Playwright: реальный вход с другого устройства, обе панели, сохранение настроек,
чтение предупреждения и переход к сеансам; 320/390/1440 px и обе темы.
Полная матрица проверок выполняется обязательным CI gate перед merge.
