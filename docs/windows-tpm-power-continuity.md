# Наблюдение TPM с событиями питания Windows

`WindowsTpmClockObservationSession` связывает сырые чтения TPM с нативной
подпиской `PowerRegisterSuspendResumeNotification`. Это диагностический
компонент в Core и явном developer probe. Он не подключён к WinUI, Windows-службе,
HTTP или автономному входу. Runtime остаётся DenyAll.

## Поведение

- Подписка создаётся до первого чтения TPM. Неуспешная регистрация, нулевой handle,
  unsafe baseline или событие во время открытия запрещают выдачу наблюдателя.
- Любое уведомление питания, включая неизвестный тип, необратимо инвалидирует
  текущий экземпляр. Callback не читает Setting и не обращается к TPM или БД.
- `Observe()` сериализует чтения, проверяет последнее успешное показание и флаг
  события до/после чтения. Ошибка TPM, смена эпохи или откат дают
  `ReanchorRequired`; последующие чтения не восстанавливают этот экземпляр.
- `Dispose()` сначала инвалидирует экземпляр, затем отменяет подписку вне lock.
  После закрытия чтения TPM не выполняются. Владелец обязан использовать `using`:
  забытое закрытие удерживает объект и регистрацию до выхода процесса.

Положительный результат — историческое наблюдение на момент последней проверки,
а не долговременное разрешение. Событие сразу после неё инвалидирует следующие
чтения. Новый процесс или объект не является доверенным восстановлением.

## Нативная безопасность

`powrprof.dll` загружается только из System32. Используются Winapi callback,
uint для кодов Windows, pointer-sized поля и DEVICE_NOTIFY_CALLBACK=2.
Нативные ошибки не раскрываются в исключениях или JSON.

Единственный статический delegate живёт весь процесс. Context — непререиспользуемый
номер из атомарного счётчика с остановкой на границе nint, а не указатель или
GCHandle. Callback ищет маршрут в словаре и только устанавливает атомарный флаг.
Ни одно managed-исключение не выходит через нативный callback.

Маршрут удаляется до unregister: даже запоздалый callback безопасен. Документация
Windows не обещает ожидания всех callback при отмене. Ошибка отмены даёт общее
исключение; объект остаётся закрытым, маршрут удалён. Регистрация ОС в таком случае
может остаться до выхода процесса, но уже не удерживает объект через маршрут.

## Проверка и ограничения

Developer probe делает два прямых чтения, затем ещё два в подписанной на события
сессии. Дополнительный boolean `powerGuardContinuityObserved` остаётся только
наблюдением. Результат доступности печатается после успешного `Dispose()`, чтобы
ошибка cleanup не могла вывести сначала успех, затем отказ. Exit 0 по-прежнему
означает доступность, а не приёмку оборудования или разрешение работы.

На ПК разработки 2026-09-26 регистрация, чтения и отмена успешно выполнены.
Реальный сон, выключение и возобновление Windows-службы этим запуском не проверялись.
Тесты с fake transport проверяют события при открытии/чтении, закрытие, поздние
callback, ошибки и изоляцию нескольких наблюдателей без изменения питания ПК.

Power API поддерживается Windows 8+, но это не меняет список поддерживаемых ОС
самого приложения. Пропущенные уведомления, завершение процесса, VM rollback,
доверенный UTC и длительность выключения этим компонентом не решены. Календарный
срок lease по-прежнему нельзя рассчитывать прибавлением TPM Clock к UTC-anchor.
