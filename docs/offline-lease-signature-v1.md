# Реальная проверка подписи автономного разрешения v1

`Ed25519OfflineLeaseSignatureVerifier` в `offline_lease_signature.py` реализует
существующий интерфейс проверки подписи. Он работает только с явно переданным
доверенным snapshot публичных ключей Cloud и не подключён к runtime, HTTP,
issuer или Windows-службе. Автономный вход остаётся DenyAll.

## Доверенные ключи

Реестр задаётся как UUID4 → ровно 32 байта raw Ed25519 public key. При создании
verifier реестр копируется в неизменяемое отображение: изменение исходного dict
не изменяет доверие. Ключ из lease, пользовательского запроса, tenant-конфигурации
или URL не принимается. Глобальный Cloud-key подписывает claims, включая tenant,
точку, устройство, пользователя, revisions, команды и сроки.

Неканонический ключ и точки малого порядка отвергаются. Один публичный ключ
нельзя зарегистрировать под двумя ID в одном snapshot: signing_key_id находится
в envelope, и такие aliases позволяли бы подменять ID без изменения подписи.
Пустой реестр допустим как deny-all; неизвестный ID всегда запрещает проверку.

Ротация — отдельное доверенное создание нового snapshot. Удалённый ID не имеет
fallback. Старый verifier не обновляется автоматически; доставка нового реестра,
защита от отката, отзыв ключей и их валидность остаются обязанностью будущего
владельца конфигурации. Немедленный отзыв Cloud-ключа без связи не обещается.

## Проверка

Verifier повторно строго валидирует envelope/claims, пересчитывает canonical
domain-prefixed bytes v1, сравнивает с переданными signing_bytes и проверяет
claims_hash. Hash остаётся проверкой согласованности, а не доказательством подписи.
PureEd25519 проверяет полные bytes; SHA-256 digest, Ed25519ph/context и v0-домен
не заменяют этот формат.

R подписи проверяется через canonical import/export; scalar S обязан быть
строго меньше Ed25519 group order. Эти проверки выполняются до библиотечной
проверки уравнения подписи. Точки и подписи обрабатывает библиотека, собственная
реализация криптографии не добавляется. Ошибки проверки дают существующий общий
`OfflineAuthUnavailableError`, без логирования payload, ключей и диагностики.

Используется уже присутствующий в locked runtime graph PyCryptodome 3.23.0
(через MinIO); зависимости и lock-файл не изменены. При будущем согласованном
обслуживании зависимостей его нужно оформить прямой зависимостью и повторить
криптографические тесты. Импорт и типизация проверяются текущими CI gates.

## Границы результата

Настоящая подпись интеграционно проверяется в decision pipeline с синтетическими
trusted-state/TPM адаптерами. Подмена tenant с пересчитанным hash, ID ключа или
подписи запрещается до обращения к локальному состоянию. Отдельные тесты
проверяют RFC 8032 vectors, malformed encodings, сроки/claims, ключи и ротацию.

Подпись сама не проверяет текущий UTC, наличие права или истечение lease:
это отдельные условия pipeline. Cloud issuer, защищённая доставка keyring,
доверенное календарное время и восстановление после выключения ещё не реализованы.
TPM Clock по-прежнему не определяет длительность выключения ПК.
