# Настраиваемые фильтры Aurum Pharma

## Цель

Фильтры должны помогать быстро находить рабочие данные на слабом компьютере и
при нестабильном интернете. Пользователь видит короткий стандартный набор, а
редкие поля добавляет через кнопку «Фильтры». Настройка относится к конкретному
аккаунту, аптеке и разделу.

## Правила интерфейса

- Поиск или главный идентификатор раздела остаётся видимым всегда.
- В стандартном наборе находятся не более двух-трёх наиболее частых фильтров.
- Любой необязательный фильтр можно показать или убрать.
- Если убрать активный фильтр, его значение сразу очищается и запрос
  пересчитывается без скрытых условий.
- «Сбросить» очищает значения, но сохраняет выбранный пользователем состав
  панели. «Вернуть стандартный набор» восстанавливает состав панели.
- Число рядом с кнопкой «Фильтры» показывает количество активных условий.
- На узком экране настройка открывается как нижняя панель и не выходит за
  границы окна. Клавиша `Escape` закрывает панель и возвращает фокус.
- Строковый поиск отправляется после паузы 300 мс. На тяжёлых отчётах фильтры
  применяются кнопкой, чтобы не выполнять запрос после каждого ввода.

## Конфиденциальность и разделение данных

В `localStorage` сохраняются только идентификаторы видимых полей. Поисковые
строки, даты, UUID, названия лекарств, пользователей, чеков и другие значения
там не хранятся. Ключ имеет вид:

```text
aurum:filter-layout:v1:<user_id>:<tenant_id>:<screen>
```

Поэтому раскладка одного пользователя или одной аптеки не переносится в другой
контекст. Доступность поля всё равно определяется разрешениями текущего
пользователя: скрытое правами поле нельзя вернуть через сохранённую настройку.

## Реализованные разделы

| Раздел      | Всегда / стандартно            | Добавляются пользователем           |
| ----------- | ------------------------------ | ----------------------------------- |
| Каталог     | поиск; тип отпуска             | —                                   |
| Партии      | товар; точка; срок годности    | пустые партии                       |
| Приходы     | номер документа; точка; статус | поставщик; период                   |
| Чеки        | номер чека; период; точка      | касса; возвраты                     |
| Аудит       | область; действие; период      | раздел данных; пользователь; аптека |
| Z-отчёты    | период; точка; кассир          | касса                               |
| Уведомления | непрочитанные; уровень         | —                                   |

Поля «аптека», «пользователь», «точка», «касса» и «поставщик» появляются только
при наличии соответствующего разрешения или области просмотра.

## Серверный контракт

Настраиваемая панель не означает произвольный конструктор SQL. Каждый раздел
объявляет собственный типизированный список разрешённых параметров. Сервер:

- принимает только известные поля и операторы;
- валидирует даты, денежные диапазоны, UUID и максимальную длину строк;
- применяет `tenant_id`, RLS и область разрешений независимо от интерфейса;
- использует параметризованные запросы без подстановки SQL-фрагментов;
- ограничивает размер страницы и добавляет `id` как стабильный второй ключ
  сортировки;
- отвечает `422` на неизвестные или несовместимые параметры.

Такой контракт защищает от SQL-инъекций, обхода прав и чрезмерно дорогих
запросов, даже если запрос отправлен вручную без интерфейса.

## Следующие разделы

После серверной пагинации и поиска тот же компонент следует подключить к:

| Раздел         | Стандартно              | Дополнительно                                |
| -------------- | ----------------------- | -------------------------------------------- |
| Пользователи   | имя/email; статус       | роль; точка; дата активности                 |
| Аптеки         | название; статус        | тариф; регион; дата создания                 |
| Точки          | название; статус        | город; тип; наличие активной кассы           |
| Кассы          | название; точка; статус | режим; последняя смена                       |
| Поставщики     | название; статус        | ИНН; город; наличие долга                    |
| Счета и тарифы | период; статус          | аптека; тариф; диапазон суммы                |
| Роли           | название; уровень       | системная/пользовательская; число назначений |

Сначала нужны отдельные API с серверной пагинацией для этих списков. Фильтрация
уже загруженных 500 записей на клиенте не подходит для слабых ПК, экономии
трафика и роста проекта.

## Где фильтры не нужны

Настраиваемую панель не добавляем в кассу POS, вход, онбординг, настройки,
карточку одного документа и мастер создания. На этих экранах она отвлекает от
одной основной операции и увеличивает риск ошибки кассира.

## Дальнейшее развитие

Именованные наборы вроде «Просрочка моей точки» можно хранить на сервере после
утверждения отдельной модели прав. Такой набор должен сохранять только
разрешённые поля, иметь владельца и область видимости, проходить повторную
валидацию при каждом открытии и автоматически удалять условия, к которым
пользователь потерял доступ. Общие наборы для аптеки сможет публиковать только
пользователь с отдельным разрешением.
