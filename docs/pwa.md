# PWA и Windows-приложение

## Текущий этап

Frontend подготовлен как installable PWA (устанавливаемое веб-приложение):

- `frontend/public/manifest.webmanifest` описывает название, цвета и иконки приложения.
- `frontend/public/sw.js` кеширует только статические frontend-файлы (`js`, `css`, иконки, шрифты).
- API-запросы, токены, чеки, цены и кассовые данные не кешируются service worker.
- Service worker отключён в dev-режиме Vite, чтобы локальная разработка не ловила старые файлы из кеша.
- `frontend/e2e/pwa.spec.ts` проверяет manifest, иконки и запрет кеширования API/HTML-страниц.

Это даёт безопасную основу для установки приложения через Chrome/Edge на Windows без отдельного desktop-интерфейса.

## Что намеренно не включено

Офлайн-касса пока не реализована:

- нет IndexedDB-очереди продаж;
- нет локального хранения чеков;
- нет фоновой синхронизации продаж после восстановления интернета;
- нет конфликт-резолюции.

Эти пункты относятся к отдельному этапу из `docs/spec-v3.md` и должны проектироваться вместе с бизнес-правилами POS.

## Следующий desktop-шаг

Когда web-версия стабилизируется, Windows-приложение делаем как WinUI 3 + WebView2 оболочку над тем же frontend:

- одна кодовая база UI;
- один backend;
- меньше риска расхождений между web и desktop;
- позже можно добавить desktop-интеграции: принтер, автозапуск, проверка сети, системные уведомления.
