# Ручные сведения о зарплате и наличных выдачах

Сотрудник открывает «Моя работа» и нажимает «Показать сведения».
Он видит только свои периоды, суммы, комментарии и историю. При закрытии
раздела и смене аккаунта сведения снова скрыты. Это онлайн-раздел:
при ошибке доступа или связи старые суммы не показываются как актуальные.

В «Выплаты сотрудникам» руководитель выбирает сотрудника, указывает период
и сумму вручную, затем записывает уже состоявшуюся выдачу наличных как выплату
или аванс. Автоматических начислений по сменам, банковских переводов,
списаний из кассы и расчёта налогов здесь нет.

Авансы входят в «Выдано наличными». Разность между суммой периода и выдачами
показывается как «Осталось выдать» или «Выдано сверх суммы», без создания долга.
Пересекающиеся периоды одного сотрудника запрещены. Сотрудник и даты периода
после создания не меняются. Изменение суммы сохраняет предыдущую версию.

Ошибочную выдачу исправляют связанной отменой с причиной; исходная запись
не удаляется. Повтор того же запроса имеет тот же код операции и не создаёт
вторую выдачу. После неопределённого результата проверяют историю, прежде чем
создавать новую запись. Уволенному или приостановленному сотруднику можно
записать окончательную выплату; собственный доступ требует активного членства.

## Доступ и границы хранения

- Владелец имеет управление; другим сотрудникам нужны отдельные tenant-wide
  разрешения `staff_pay.view` или `staff_pay.manage` из конструктора ролей.
- Platform developer/administrator и режим поддержки не получают зарплатные
  данные. `aurum_support` не имеет прав на приватные таблицы и команды.
- Периоды, выдачи и версии изолированы по аптеке и пользователю через RLS.
  Команды проверяют текущую сессию, членство, опубликованные разрешения и статус
  аптеки. Финансовая история неизменяема, изменение периода использует версию.
- Общий аудит содержит только технические метаданные без сумм и комментариев.
  Ответы API имеют `Cache-Control: no-store`; браузер хранит данные в памяти,
  ключи запросов разделены по аккаунту, аптеке и режиму чтения.

## Код и проверка

Backend: `app/domains/staff_pay`, миграция `0160_manual_staff_pay`.
API: `/api/v1/staff-pay`, собственные маршруты `/mine`, приватные истории
`/entries` и `/revisions`. Поиск сотрудника использует POST без имени в URL.
Frontend: `features/staff-pay`, страницы `/staff-pay` и `/my-work`.

Проверки: `tests/domains/staff_pay`, frontend `tests/features/staff-pay`,
`e2e/staff-pay.spec.ts`. Проверка rollback миграции допускается только на
одноразовой БД; downgrade отказывает при наличии финансовой истории.
