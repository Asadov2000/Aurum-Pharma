# Полный подписанный Edge snapshot: контрольный замер 2026-09-23

## Методика

`scripts/benchmark-edge-read-model.ps1 -FullSnapshot` создаёт одноразовые
PostgreSQL и внутреннюю Docker-сеть без host ports и общих томов. До подключения
Python проверяет фиксированное имя тестовой БД, host и роли. Общая dev/demo БД,
Compose-проекты и `.env` не используются; ресурсы удаляются в `finally`.

Драйвер создаёт 100 000 синтетических товаров, по одному штрихкоду на товар и
250 000 партий одной точки. Он формирует типизированную проекцию, режет её на
чанки штатным кодом, подписывает манифест настоящим случайным Edge credential,
проверяет подпись, каждый чанк, схему и scope, затем устанавливает снимок через
`SyncEdgeRepository.install_read_snapshot` под RLS-контекстом Edge. После
освобождения исходных объектов и очистки внутрипроцессного кэша выполняется
первое чтение `LocalReadModel.catalog`: оно повторно проверяет подпись и все
сохранённые чанки. Следующие 30 чтений измеряют работу с уже проверенным
снимком. Замер фиксирует RSS только Python-процесса; потребление PostgreSQL,
Docker Desktop и Windows не включено.

```powershell
.\scripts\benchmark-edge-read-model.ps1 -FullSnapshot
```

## Результат и решение

База: `514fe26`; backend image
`sha256:33aec2a44e0641a3e2b4ed39492ee37aba06d41d5e349b25e11760565919a0b0`.
Полный успешный прогон создал 701 чанк. Генерация данных заняла 13,719 с,
формирование и криптографическая проверка — 32,725 с, атомарная установка —
247,300 с. Первая полная проверка сохранённого снимка вместе с чтением первой
страницы каталога заняла 10,296 с. Последующие 30 открытий первой страницы без
поискового запроса дали p50 875,8 мс и p95 1 919,1 мс. Пик RSS Python-процесса —
3 207,1 МБ, перед первым чтением после освобождения исходных объектов —
1 621,2 МБ.
Драйвер ограничен 5 GiB и 1 CPU, PostgreSQL — 8 GiB и 4 CPU с
`shared_buffers=512MB`.

Установка и целостность на этом объёме подтверждены в Linux-контейнерах на
Windows-хосте. Но первое чтение длительностью 13 с не подходит для немедленного
открытия каталога после установки или перезапуска API. В пилотном допуске
остаются два блокера: проверять полный сохранённый снимок до выдачи готовности
локального API и при активации новой ревизии, сохраняя fail-closed поведение;
ускорить первую страницу каталога без поискового запроса, которая даже после
проверки снимка превышает ориентир ADR-0043 в 300 мс. Нельзя просто отключить
повторную криптографическую проверку ради скорости.

Это **не** Windows acceptance и не проверка полной нагрузки Edge: Cloud-подготовка
и Edge-установка здесь идут в одном Python-процессе, тогда как в эксплуатации
они разделены. Пик RSS поэтому не равен потреблению Edge-службы. Нужны замеры
на целевом Windows 11 ПК с backend, PostgreSQL, клиентом и sync worker, затем
WAN/restart/restore drill. `acceptance_claimed=false`; автономные продажи не
включаются этим тестом.
