# Контракт автономной работы точки

Статус: критерии проектирования и приёмки будущего Branch Edge. Текущий web
runtime их полностью не реализует. Backend уже принимает, проверяет и атомарно
активирует подписанные read-only snapshots `foundation/catalog/inventory` для
конкретных tenant, branch и Edge node. Публикация Cloud-данных, локальные API/UI,
offline-вход и денежные команды остаются следующими блоками. Архитектурное
решение находится в [ADR-0043](adr/0043-thirty-day-branch-edge-continuity.md).

## Состояния интерфейса

Каждый рабочий раздел использует один из явных статусов:

| Статус | Значение | Допустимое поведение |
|---|---|---|
| Актуально | Edge доступен, локальные данные применены | Разрешённые локальные команды доступны |
| Ожидает отправки | Операция сохранена Edge, Cloud ещё не подтвердил приём | Показывать очередь и `operation_id`; не повторять эффект |
| Данные Cloud устарели | Локальный snapshot внешних данных имеет известное время | Чтение доступно, зависимые изменения ограничены |
| Результат неизвестен | Внешняя оплата или фискальная команда могла выполниться | Только сверка по прежнему идентификатору |
| Требует сверки | Нарушены sequence, checksum или ownership | Остановить затронутый поток, сохранить остальные безопасные функции |
| Только чтение | Истёк authorization lease или отсутствует capability | Локальные данные и экспорт доступны без новых защищённых команд |
| Восстановление | Диск, БД, ключ или backup не прошли проверку | Новые внешние эффекты запрещены |

Страница не должна оставаться в бесконечном spinner, скрывать давность данных или
автоматически повторять денежную команду после сетевой ошибки.

## Полномочия и совмещение ролей

| Пользователь | Без WAN доступно | Всегда запрещено локально |
|---|---|---|
| Кассир | Только команды из подписанного snapshot для своей точки и кассы | Назначение ролей, смена точки, расширение собственного доступа |
| Кассир с дополнительными функциями | Одна составная роль точки содержит нужные permissions; tenant-wide и branch scopes учитываются сервером | Несколько локально придуманных назначений и команды вне branch scope |
| Владелец аптеки | Разрешённые операции своих точек и просмотр локальных данных | Platform-функции Aurum и самостоятельный обход истёкшего lease |
| Управляющий/кладовщик | Приходы, партии и справочники только по выданным permissions | Денежные команды без POS permission |
| Сотрудник Aurum | Только локальная техническая диагностика без данных аптеки и экспорт подписанного диагностического пакета | Offline tenant-доступ, BYPASSRLS на Edge и старая support-сессия |

Сервер и Edge проверяют permission для каждой команды. UI использует тот же
snapshot только для отображения. Отзыв или уменьшение прав применяется при
первом полученном обновлении и не может быть отменён локально. Владелец с нужным
permission может заблокировать сотрудника непосредственно на Edge своей точки;
Cloud-отзыв, которого Edge ещё не получил, технически не может подействовать.

## Поведение при отказах

| Событие | Ожидаемое поведение | Доказательство |
|---|---|---|
| WAN отсутствует 24 часа / 7 / 30 суток | Локальные страницы и разрешённые Edge-команды работают; Cloud-снимки имеют дату | Автоматический прогон с виртуальным временем и реальный soak |
| Закрытие приложения | UI можно открыть снова, незавершённый локальный ввод восстановлен | E2E после принудительного завершения процесса |
| Перезагрузка основного ПК | Службы стартуют автоматически, commit не потерян | Тест выключения питания и сверка БД |
| Потерян ответ команды | Повтор с тем же ключом возвращает прежний результат | Fault injection до и после commit |
| WAN появился во время работы | Sync запускается в фоне и не меняет путь кассовой команды | Нагрузка UI одновременно с backlog upload |
| Sync оборвался | Продолжается с подтверждённого watermark | Несколько обрывов одного 30-дневного backlog |
| Потеря LAN дополнительной кассой | Денежные команды блокируются; отдельная БД не создаётся | Изоляция клиента от основного ПК |
| Основной ПК недоступен | Понятный recovery-экран; автоматического failover нет | Drill восстановления и writer handover |
| Диск заполнен | Новые внешние эффекты блокируются до безопасного освобождения/restore | Fault injection по порогам диска |
| Повреждение БД/backup | Восстановление только из прошедшей checksum-копии | Restore drill на другом ПК |
| Часы переведены назад | Lease и fiscal сроки не продлеваются | Trusted-time/anti-rollback тест |
| Права отозваны во время offline | Уже полученный отзыв действует сразу; неполученный ограничен сроком lease | Тест revision и истечения |
| SMS/email недоступны | Offline-вход использует только разрешённый локальный credential | Тест без внешней сети и DNS |
| Неизвестен результат банка/ККУ | Состояние `результат неизвестен`, сверка по тому же operation id | Провайдерский sandbox и fault injection |

## Первый вертикальный сценарий

Первый выпускаемый сценарий ограничивается одной точкой, одной кассой и наличной
продажей:

1. Подписанный Windows-клиент запускает локальный frontend и проверяет Edge.
2. Разрешённый кассир входит по заранее выпущенному локальному credential.
3. Кассир открывает смену, находит товар и выполняет наличную продажу.
4. Edge одной транзакцией сохраняет продажу, FEFO-партии, остаток, оплату,
   внутренний чек, audit, command ledger и outbox.
5. Перезапуск ПК подтверждает сохранность результата и повторную печать того же
   чека без новой продажи.
6. После восстановления WAN событие доставляется Cloud; повтор доставки не
   создаёт второй эффект, отчёт показывает время синхронизации.

Сценарий не считается готовым без положительного offline-auth verifier,
изолированной Edge DB identity, подтверждённого fiscal adapter и всех gate из
ADR-0001/0002/0005/0012/0013/0014. До этого допустим только shadow/read-only
режим на искусственных данных.

## Реальное состояние на момент принятия

Уже существуют shadow-sync продаж, sequence/checksum, quarantine, writer
handover, атомарный Edge cash dispatcher в БД и fail-closed offline-auth
pipeline. Read-only transport хранит подписанные snapshots отдельно от writer
activation, проверяет точный набор компонентов, непрерывность chunks и SHA-256,
а активный указатель меняет одной транзакцией только после полной проверки.
При этом runtime публикует только профили `cloud` и `edge_shadow`: Edge HTTP
mutations блокируются, положительный offline verifier отсутствует, генератор
snapshot, Edge-to-Cloud ingest и локальный backup не выпущены. Packaged WinUI
host существует в `desktop/`, но пока хостит общий online frontend; локального
Edge runtime и клиентского установщика ещё нет.

Поэтому первый исполняемый блок — воспроизводимый read-only Edge на чистом
Windows-ПК с полным snapshot, локальной сборкой UI, месячным синтетическим
backlog и restore drill. Денежный writer включается отдельным последующим gate.

## Профиль нагрузки пилота

До реализации QA фиксирует верхние границы для одной точки:

- число товаров, штрихкодов, партий и сотрудников;
- продажи и складские операции за 30 дней;
- максимальное число одновременно работающих касс;
- объём фото, PDF и экспортов;
- минимальные CPU, RAM, свободное место и версия Windows;
- допустимые RPO/RTO и время синхронизации backlog.

Нагрузочный набор не содержит реальные персональные или финансовые данные.
Результаты на компьютере разработчика не заменяют проверку минимальной клиентской
конфигурации.
