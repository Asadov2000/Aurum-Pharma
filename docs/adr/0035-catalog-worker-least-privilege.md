# ADR-0035: Минимальные права обработчика каталога

- Статус: принято
- Дата: 2026-09-07
- Связано: ADR-0009, ADR-0030, ADR-0034, миграция 0142

## Причина

Отдельный процесс импорта сохранял общую роль `aurum_app` и ключи хранилища
приложения. Ошибка в парсере могла дать доступ к несвязанным таблицам и операциям
над файлами, хотя обработчику нужны только задания, товары, штрихкоды и чтение
загруженного импорта.

## Решение

1. `catalog-worker` подключается только как `aurum_catalog_worker` через
   `DATABASE_URL_CATALOG_WORKER`. Роль имеет `NOINHERIT`, `NOBYPASSRLS`, лимит
   двух соединений, без membership и прав на DDL, TEMP или параметры сервера.
2. Чтение разрешено только для `catalog_import_job`, `tenant_catalog`, `barcode`.
   Запись ограничена колонками исполнения задания и полями, которые заполняет
   импорт. Worker не создаёт задания, не меняет tenant, источник файла, UUID и
   deadline исполнения; не удаляет записи. Создание товара использует явный
   набор колонок, без неявной записи ORM в поля изображения и master-каталога.
3. RLS остаётся обязательной. Из прикладных функций доступны только
   `current_tenant_id()` и `current_app_user_id()`, необходимые для политик и
   метаданных изменений. Audit-триггеры продолжают работать; прямого доступа
   к журналу у worker нет.
   В `current_tenant_id()` проверка support-контекста вынесена во вложенный
   `IF`: подготовка общего выражения `AND` иначе требует EXECUTE на support-функцию
   даже без support-контекста. Поддельный контекст по-прежнему закрывает доступ.
4. Роль ограничивает SQL-запрос 30 секундами и ожидание блокировки 5 секундами.
   Простой внутри транзакции ограничен 180 секундами: это больше принудительного
   лимита задачи 150 секунд, поскольку чтение файла происходит после начала
   транзакции.
5. Отдельные `CATALOG_MINIO_ACCESS_KEY` и `CATALOG_MINIO_SECRET_KEY` получают
   только `s3:GetObject` для `arn:aws:s3:::<bucket>/*/imports/*`. Нет прав на
   список, запись, удаление объектов или администрирование. SDK получает явный
   регион `us-east-1`, чтобы не требовать `GetBucketLocation`.
6. Dev, demo, E2E и production используют один механизм выдачи политики.
   Обработчик запускается после успешной настройки identity. Новые demo-секреты
   добавляются к существующим, без пересоздания данных или смены прежних ключей.
   Bootstrap БД нормализует права, включая отдельные column ACL.

## Проверки и границы

При обновлении остановить старый catalog-worker, добавить четыре новых секрета
(`AURUM_CATALOG_WORKER_PASSWORD`, согласованный `DATABASE_URL_CATALOG_WORKER`,
оба `CATALOG_MINIO_*`), выполнить role bootstrap и `upgrade head`, затем запустить
новый init и worker. Существующие production-секреты не пересоздавать генератором.
Штатный demo-launcher добавляет недостающие ключи сам. Повторная настройка MinIO
отказывается работать с identity, имеющей лишнюю прямую policy или группу;
оператор должен сначала устранить это несоответствие.

Проверки должны использовать реальные подключения ограниченной DB-роли и
реальные запросы MinIO SDK: разрешённый импорт, запрет лишних таблиц/колонок,
RLS, запрет чтения другого префикса и записи/удаления/list/admin в хранилище.
Миграционный downgrade допускается только на одноразовой тестовой БД.

Эта роль и MinIO identity общие для обработчиков разных аптек. Политика
хранилища разрешает import-объекты всех tenants; прикладная проверка job и пути
связывает конкретную операцию с tenant. RLS проверяет установленный tenant
context, но не доказывает его подлинность при полном захвате процесса.

Разделение сетей, Redis ACL, реальный provider уведомлений и внешний допуск
пилота остаются отдельными обязательствами ADR-0030. Это решение не означает
готовность к публичному пилоту само по себе.
