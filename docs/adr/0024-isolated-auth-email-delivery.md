# ADR-0024: Изолированная доставка кодов входа

## Статус

Принято.

## Контекст

Код входа является краткоживущим credential. Передача email и кода открытым
текстом в аргументах Celery расширяет последствия компрометации Redis или
обычного worker. При этом локальная разработка должна проверять реальную
структуру писем без доступа к внешнему SMTP.

## Решение

1. Функция выдачи кода всегда сохраняет его хеш, чтобы ответ API не раскрывал
   существование аккаунта. Зашифрованный payload в `auth_email_outbox`
   создаётся только для активного или приглашённого `app_user`. Предыдущая
   неотправленная доставка для того же email отменяется.
2. `aurum_app` может только вызвать функцию выдачи. Прямого доступа к outbox у
   него нет.
3. Только роль `aurum_mailer` может забрать и завершить доставку через узкие
   `SECURITY DEFINER` функции. После terminal-состояния ciphertext удаляется.
4. Обычные workers не получают SMTP credentials и не слушают mailer-очередь.
5. Development использует локальный Mailpit без TLS внутри Docker network.
   Staging и production требуют STARTTLS, отдельные SMTP credentials и
   отказываются запускаться с небезопасной конфигурацией.
6. Email и код не записываются в application logs, Celery payload или ответы
   API вне development.

## Последствия

- Доставка может быть повторена после временной ошибки без повторной выдачи
  кода.
- Сбой SMTP не откатывает транзакцию выдачи кода.
- Компрометация обычного Celery worker не раскрывает SMTP credentials или
  plaintext-коды из очереди.
- Для production необходим настроенный SMTP-провайдер; Mailpit никогда не
  входит в production Compose.
