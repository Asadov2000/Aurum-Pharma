# ADR 0030: Границы фоновых процессов Celery

- Статус: принято
- Дата: 2026-09-04
- Связано: ADR-0009, ADR-0015, ADR-0019, ADR-0024

## Контекст

Общий Celery-процесс получал конфигурацию FastAPI целиком: обе DB-роли, JWT,
MFA, MinIO, metrics и ключ шифрования outbox. Планировщик `celery-beat` наследовал
тот же набор, хотя ему нужен только broker. Импорт каталога выполнялся в общем
worker, поэтому уязвимость парсера файла могла открыть секреты несвязанных
контуров.

Отдельная очередь сама по себе не является границей безопасности: процесс должен
иметь отдельное приложение Celery, минимальную конфигурацию и точный allowlist
секретов во всех режимах запуска.

## Решение

1. Общий `celery-worker` обслуживает только системные задачи из очереди
   `default`. Ему передаются только URL системной DB-роли и Redis.
2. Импорт каталога обслуживает отдельный `catalog-worker` через
   `app.tasks.catalog_app` и очередь `catalog-worker`. Процесс получает только
   tenant-scoped DB URL, Redis и MinIO credentials.
3. `celery-beat` получает только Redis и не зависит от PostgreSQL или MinIO.
4. Billing и mailer продолжают использовать собственные приложения, очереди и
   выделенные DB-роли.
5. Конфигурации worker являются fail-closed в staging/production: неверная
   DB-identity, Redis без пароля и стандартные MinIO credentials останавливают
   процесс до начала обработки задач.
6. HTTP-router не импортируется как побочный эффект загрузки моделей каталога и
   склада. Это позволяет worker загружать доменный код без JWT и HTTP-конфига.
7. Dev, demo, E2E и production обязаны поднимать `catalog-worker`. CI проверяет
   точное равенство наборов production-секретов, а не только отсутствие
   нескольких известных опасных значений.

## Остаточные обязательные меры

Эта ADR уменьшает последствия компрометации процесса, но не завершает
least-privilege модель. До внешнего пилота обязательны отдельные изменения:

- заменить `aurum_support` у системного worker на `aurum_worker` с `NOBYPASSRLS`
  и доступом только к узким `SECURITY DEFINER` командам;
- заменить общую `aurum_app` у импорта на специализированную DB-роль;
- выдать catalog-worker read-only MinIO credentials только для import-объектов
  и проверять tenant-bound путь до чтения;
- разделить DB, broker и storage сети;
- ограничить очереди Redis отдельными ACL или отдельными broker-инстансами.

До выполнения этих пунктов текущую границу нельзя считать достаточной для
публичного production или пилота с реальными данными.

## Последствия

- Компрометация `celery-beat` больше не раскрывает DB, JWT, MFA или MinIO.
- Парсер импорта не получает support DB, JWT, MFA, email и metrics secrets.
- Остановка catalog-worker задерживает только импорт; API, касса, billing и
  почтовая доставка продолжают работать.
- Добавляется отдельный контейнер и небольшой постоянный расход памяти.
- Изменение маршрута задачи без запуска соответствующего worker блокируется
  тестами запускателей и Compose-контрактом.
