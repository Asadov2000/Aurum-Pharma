# ADR-0043: Автономность точки до 30 дней

- Статус: принято
- Дата: 2026-09-20
- Уточняет: ADR-0001, ADR-0002, ADR-0005, ADR-0012, ADR-0013, ADR-0014
- Заменяет: требование ADR-0001 об обязательном выделенном mini-PC для двух и
  более касс

## Контекст

Аптека должна продолжать работу при отсутствии интернета до 30 календарных
дней. На точке может быть только один или несколько обычных Windows-ПК без
отдельного локального сервера. Приложение обязано открывать интерфейс и локальные
данные без загрузки ресурсов из Cloud, сохранять операции после перезапуска и
безопасно синхронизироваться после восстановления связи.

Тридцать дней — целевой срок сохранности и доступности локального контура, а не
безусловное разрешение любой денежной, банковской или фискальной операции.
Внешние провайдеры и применимые требования могут задавать меньший срок для
конкретной операции. Внутренний чек Aurum не заменяет фискальный чек.

## Решение

### Топология точки

На каждой точке существует один Branch Edge и один активный writer:

- на точке с одной кассой Edge работает фоновыми Windows-службами на том же ПК;
- на точке с несколькими кассами один назначенный основной ПК содержит Edge и
  PostgreSQL, а остальные Windows-клиенты обращаются к нему по защищённой LAN;
- выделенный mini-PC остаётся рекомендуемым вариантом для нескольких касс, но
  не является обязательным условием установки;
- основной ПК не должен переходить в сон во время работы точки, запускает службы
  после перезагрузки и должен быть подключён к UPS;
- клиенты никогда не подключаются к PostgreSQL напрямую.

Нельзя автоматически создавать независимый writer на дополнительной кассе при
потере LAN или основного ПК. Восстановление на другом ПК требует проверенной
резервной копии и явной передачи `writer_epoch` по ADR-0002.

### Состав установленного решения

Установка профиля «основной ПК точки» включает:

1. подписанный WinUI 3 host с WebView2;
2. локальную подписанную сборку существующего React frontend;
3. Edge-профиль существующего FastAPI backend;
4. локальный PostgreSQL, sync worker, backup и health checks;
5. ограниченные адаптеры принтера, сканера, денежного ящика и будущей ККУ.

Профиль «дополнительная касса» содержит Windows-клиент и оборудование, но не
вторую финансовую БД. Бизнес-логика остаётся в существующем backend. WinUI host
не становится владельцем продаж, остатков, авторизации или синхронизации.

Frontend, шрифты, значки, локализация и обязательные изображения входят в
установку. Рабочие страницы не загружают обязательные ресурсы из интернета.
Windows-клиент всегда открывает локальный origin Edge; доступность Cloud не
меняет адрес кассового API и не вызывает переключение режима.

### Область автономной работы

Целевое состояние после поэтапного выпуска:

| Область | Без WAN | Источник истины |
|---|---|---|
| Касса, смены, наличные продажи | Локальная запись при действующих auth и fiscal capabilities | Edge |
| Остатки, партии, сроки, списания | Полная работа в пределах точки | Edge |
| Приходы и возвраты поставщику | Черновики и разрешённые локальные операции | Edge |
| Каталог, цены, поставщики | Последний snapshot; изменения идут версионированными командами и могут ожидать сверки | Cloud с локальной проекцией |
| Локальные отчёты и аудит | Строятся из Edge-БД с отметкой локального периода | Edge |
| Другие точки и общая аналитика | Последний Cloud snapshot только для чтения с явной давностью | Cloud snapshot |
| Сотрудники и роли | Последний подписанный authorization snapshot; локальное расширение прав запрещено | Cloud |
| Billing Aurum, SMS, внешние банки | Страница открывается, но требующие провайдера действия недоступны | Cloud/провайдер |

Каждый раздел обязан открываться без бесконечной загрузки. Если свежий Cloud
ответ необходим, страница показывает последние доступные данные, время их
получения и конкретно недоступное действие. Нельзя отображать устаревший snapshot
как свежий или заменять неизвестные суммы нулями.

### Offline-auth и роли

Эффективные полномочия вычисляются по permissions и областям точек, а не по
названию роли. Текущая модель допускает одну составную роль пользователя на
конкретной точке и отдельное tenant-wide назначение; дополнительные функции на
той же точке владелец включает в составную роль. Tenant-wide и branch scopes
объединяются для одной capability, а требования нескольких capabilities
пересекаются. Настоящие несколько назначений на одной точке потребуют отдельной
миграции и тестов, поэтому offline-клиент не должен изобретать их локально.

ADR-0005 v0 с пределом 72 часа остаётся fail-closed и не включается простой
сменой срока. Для цели 30 дней требуется отдельная версия authorization lease:

- пользователь и устройство заранее допускаются владельцем при наличии права;
- Cloud выдаёт подписанный lease на точные tenant, branch, register, user,
  revision и узкие команды, максимум на 30 дней;
- локальная проверка использует Edge-специфичный credential, который нельзя
  применить для входа в Cloud, плюс TPM-bound ключ, trusted time и anti-rollback;
- локальная повторная аутентификация обязательна по политике смены; SMS и email
  не считаются доступными без WAN;
- отзыв, полученный Edge, действует немедленно и необратимо; неполученный отзыв
  невозможно честно обещать во время полного отсутствия связи;
- владелец с соответствующим permission может немедленно локально заблокировать
  сотрудника на своей точке; событие попадает в outbox и не расширяет права;
- по истечении lease новые защищённые команды блокируются, а просмотр и экспорт
  локальных данных остаются доступны согласно последнему snapshot;
- опасные команды требуют отдельной capability и повторного подтверждения;
  локальный владелец не может сам добавить себе Cloud permission.

До реализации, криптографической проверки и аппаратных тестов положительного
verifier runtime продолжает использовать `DenyAllOfflineAuthVerifier`.

### Синхронизация и конфликты

Финансовые и складские операции используют transactional outbox/inbox и
`at-least-once` доставку. Уникальные `operation_id`, `event_id`,
`origin_node_id + writer_epoch + sequence` и `payload_hash` обеспечивают один
бизнес-эффект при повторах. Потерянный ответ приводит к чтению прежнего
результата, а не к слепому повтору.

После восстановления WAN Edge сначала отправляет неизменяемые операции своей
точки небольшими возобновляемыми пакетами, затем получает Cloud-команды. Разрыв
sequence, несовпадение checksum или конфликт владельца останавливает watermark
и создаёт quarantine incident по ADR-0027. Last-write-wins для денег, остатков,
прав и фискальных результатов запрещён.

### Сохранность и восстановление

- commit операции переживает закрытие UI, перезапуск служб и отключение питания;
- локальный backup выполняется автоматически и шифруется ключом устройства;
- минимум одна актуальная копия хранится на другом разрешённом носителе;
- целевой RPO локальной второй копии — не более 5 минут, RTO проверенного
  восстановления на запасном ПК — не более 30 минут;
- заполненный диск, повреждение БД или неизвестный fiscal/payment result
  блокируют новые внешние эффекты и переводят Edge в recovery;
- удаление приложения по умолчанию не удаляет рабочую БД и backups;
- восстановление всегда проверяет tenant/branch/node, checksum, sequence и
  совместимость схемы до выдачи writer-права.

Абсолютный RPO 0 при одновременной физической потере основного ПК и всех
локальных копий без внешнего канала невозможен. Этот остаточный риск показывается
в пилотном допуске, а не скрывается интерфейсом.

### Производительность и проверка

На минимальной поддерживаемой конфигурации после прогрева:

- запуск локального shell до доступной навигации — не более 5 секунд;
- службы Edge готовы не позднее 60 секунд после загрузки Windows;
- переход между уже установленными разделами — p95 не более 300 мс до видимого
  локального состояния;
- поиск по локальному каталогу — p95 не более 300 мс;
- точный поиск штрихкода — p95 не более 150 мс;
- подтверждение локальной команды без внешнего оборудования — p95 не более 1 с,
  чек виден не позднее 2 секунд;
- sync не блокирует UI и не удерживает транзакции пользовательских команд;
- sync не ухудшает p95 checkout больше чем на 20%; 30-дневный backlog из
  300 000 событий при 10 Mbps синхронизируется не дольше 60 минут частями с
  возобновлением после обрыва и без дублей.

Базовый QA-профиль: Windows 11, 4 CPU, 8 GB RAM, SSD, 100 000 товаров,
250 000 партий и 30 000 продаж за автономный период. Точные размеры уточняются
профилем пилотной аптеки. Пороги проверяются на обычном аптечном ПК, а не только
на машине разработчика.

## Порядок реализации

1. Зафиксировать пользовательские и аварийные сценарии в
   `docs/offline-operations-contract.md`.
2. Проверить Windows toolchain и создать packaged WinUI host без финансовых
   полномочий; он загружает локальную сборку и показывает состояние Edge.
3. Развернуть read-only Edge, snapshots, checksum, backup/restore и месячный
   объём тестовых данных.
4. Реализовать и аппаратно проверить authorization lease v1.
5. Выпустить одну capability: атомарная наличная продажа на одной кассе.
6. По одной добавлять смены, возвраты, приход, списания и локальные изменения
   справочников с отдельными правилами конфликтов.
7. Проверить несколько касс, WAN/LAN/power/disk faults, восстановление и
   фискальный адаптер до коммерческого пилота.

Детализация выполняется отдельными ADR до соответствующей реализации:
authorization lease v1; владение данными и локальные предложения справочников;
Edge-to-Cloud ingest/backpressure; Edge backup/recovery/update. ADR-0043 задаёт
общую границу, но не включает эти механизмы автоматически.

## Последствия

Приложение проектируется как локальный клиент Branch Edge, поэтому перенос Cloud
на другой сервер не требует переустановки при сохранении домена и протокола.
Один установщик может распространяться через сайт, портал или флеш-накопитель;
подлинность определяется цифровой подписью и manifest обновления, а не местом
скачивания.

Цена решения — обязательные локальная БД, служба, backup, device identity,
поддержка основного ПК и строгий capability rollout. Windows-оболочка сама по
себе не даёт offline-работу, а цель 30 дней не отменяет внешние фискальные и
платёжные ограничения.
