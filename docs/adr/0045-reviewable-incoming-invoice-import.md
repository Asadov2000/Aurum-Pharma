# ADR-0045: Загрузка табличной накладной в проверяемый приход

- Статус: принято
- Дата: 2026-09-24
- Связано: ADR-0039, ADR-0040, ADR-0044

## Причина

Ручной ввод каждой позиции накладной медленный, а поставщики используют разные
Excel/CSV-форматы. При этом название из файла не доказывает совпадения с
карточкой каталога, а количество, единица, партия, срок и цены требуют проверки
человеком. Повтор запроса после потери ответа не должен удваивать строки.

## Решение

1. Табличный файл сначала разбирается без изменения БД. Сотрудник видит найденные
   столбцы и пример строк, проверяет сопоставление столбцов и явно запускает
   импорт. Поддерживаются CSV и XLSX в ограниченном размере; файл разбирается
   внутри Aurum, без внешнего распознавания и без новой зависимости.
2. Импорт добавляет незавершённые `incoming_draft_row` только в существующий
   черновик прихода с выбранными точкой и поставщиком. Исходное название товара
   сохраняется как ограниченная строка. Автоматического создания карточки,
   слияния похожих товаров и проведения на склад нет.
3. Сотрудник связывает каждую позицию с подходящей карточкой или создаёт новую
   через существующий процесс и права `catalog.create`. Розничная цена не
   выводится из закупочной. Неполные строки блокируют принятие прихода по
   ADR-0039. Название и числа из файла остаются предложением, а не подтверждением.
4. Весь пакет записывается атомарно под блокировкой документа. Повтор точного
   файла в том же документе не добавляет строки даже с новым ключом операции и
   после завершения отдельной строки. Другая карта колонок для уже загруженного
   файла даёт конфликт. Повтор ключа исходной загрузки с другим файлом тоже даёт
   конфликт. Ключ, применённый только к пустому повтору, отдельно не хранится.
   Завершённые и удалённые строки не возрождаются. Лимит 500 незавершённых
   строк сохраняется.
5. Права `incoming.create`, область точки, tenant/RLS и сокрытие закупочных цен
   остаются прежними. Значения накладной не попадают в логи и `localStorage`.
   Ошибка файла не раскрывает содержимое строк.

## Граница этапа

Фото/PDF, OCR, хранение исходника и шаблоны конкретных поставщиков требуют
отдельного решения и проверки точности на разрешённых образцах. Этот этап даёт
ручное сопоставление столбцов для разных табличных форматов.

## Проверки

- Типовые русские и таджикские заголовки, ручное сопоставление и неверный файл.
- Повтор, конфликт, параллельный импорт и ограничение числа строк.
- Неизвестный товар, дальнейшее сопоставление с каталогом и блокировка проведения.
- Права, tenant/точка, закупочная цена и сквозной браузерный сценарий.
