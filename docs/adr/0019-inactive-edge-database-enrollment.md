# ADR-0019: Неактивное зачисление DB-идентичности Edge-узла

- Статус: принят
- Дата: 2026-08-26
- Уточняет: ADR-0013, ADR-0014

## Контекст

Будущий Edge cash dispatcher обязан определять физический узел по неизменяемому
`session_user`, а не по UUID или GUC из запроса. До реализации dispatcher нужно
проверить жизненный цикл индивидуальной PostgreSQL-роли, не открывая offline POS.

## Решение

Инфраструктурная команда `manage-edge-cash-identity` выполняется только
bootstrap-superuser в одной транзакции и под advisory lock конкретного узла.
Для активного `edge_writer`, уже привязанного к кассе, она:

1. выводит имя `aurum_edge_node_<uuid_hex>` только из `sync_node.id`;
2. создаёт роль без пароля и `CONNECT`, а до конца той же транзакции переводит
   её в `NOLOGIN` с лимитом одного будущего соединения;
3. оставляет единственное членство в `aurum_edge_cash_executor` без `ADMIN` и
   без права `SET ROLE`;
4. сохраняет имя и OID роли в неизменяемом `edge_cash_node_identity`;
5. при повторе принимает только полностью совпадающую существующую привязку.

Роль пока не может подключиться к БД и не получает ни одного ACL. Краткое
состояние `LOGIN` существует только внутри недоступной извне транзакции, потому
что текущий identity-триггер проверяет будущий runtime-контракт. После commit
роль всегда `NOLOGIN`; это блокирует также certificate, peer, trust и иные
беспарольные способы входа.

Отзыв разрешён только после перехода `sync_node.status` в `revoked`. Он ставит
`NOLOGIN`, удаляет capability membership, обрывает существующие соединения и
оставляет identity ledger для аудита и защиты от повторного использования OID.

Role bootstrap сохраняет ровно одно допустимое membership только для активных
узлов с валидной identity-привязкой. Неизвестные роли с Edge-префиксом
принудительно переводятся в `NOLOGIN` и лишаются доступов.

## Граница выпуска

Этот этап не выдаёт credential, не даёт `CONNECT`, не создаёт dispatcher,
HTTP route или положительный offline-auth verifier. Действующая web-касса и
облачный checkout не изменяются. Следующий этап обязан добавить атомарный
`SECURITY DEFINER` dispatcher и тесты через настоящее отдельное соединение
узловой роли до любого включения offline POS.
