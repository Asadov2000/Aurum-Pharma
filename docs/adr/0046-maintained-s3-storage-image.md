# ADR-0046: Поддерживаемый образ S3-хранилища

- Статус: принято
- Дата: 2026-09-24
- Связано: ADR-0008, ADR-0022, ADR-0035

## Причина

Ранее закреплённые образы `quay.io/minio/minio` и `quay.io/minio/mc` перестали
отдаваться реестром. CI останавливается до тестов приложения, а новый сервер не
сможет воспроизвести установку. Уже запущенное локальное demo использует
закешированный образ и существующий именованный том с объектами.

## Решение

1. Использовать опубликованные образы PGSTY SILO Server и MCLI релиза
   `RELEASE.2026-09-16T00-00-00Z`, закреплённые полными SHA-256 digest.
   SILO — поддерживаемый S3-совместимый форк MinIO. Имена сервисов, endpoint,
   bucket, секреты, политики доступа и путь тома `/data` остаются прежними.
2. Внутренние команды `minio server` заменить на `silo server`. Контейнерный
   клиент сохраняет команду `mc`. Не включать необязательные изменения поведения
   SILO без отдельного решения.
3. До первого переключения существующего demo-тома сохранить его отдельную
   копию. На копии проверить запуск, доступ к прежним объектам и запись/чтение.
   После успешного CI обновлять demo штатным current-main launcher с `SkipSeed`,
   затем проверить хранилище, API и frontend. Не удалять и не пересоздавать том.
4. Обратный запуск старого MinIO на томе после записей нового сервера не считать
   безопасным откатом. Для отката использовать сохранённую копию тома вместе с
   прежним образом и согласованным состоянием приложения.

## Проверки и границы

- Проверить наличие `/bin/sh`, `silo` и `mc` в точных образах релиза.
- Изолированно проверить TLS, IAM каталога, backup/restore и полный CI gate.
- Сохранность существующего demo оценивается на копии тома до переключения и
  повторно на работающем сервисе после него. Тестовая копия не заменяет
  независимую резервную копию для production.
