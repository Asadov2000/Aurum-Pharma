# ADR 0021: Области настроек и право владельца

- Статус: принято
- Дата: 2026-08-23
- Связано: ADR-0009, ADR-0013, ADR-0020

## Контекст

Раздел «Настройки» объединял параметры всей аптеки и открывался по разрешению
`settings.update`. Такое разрешение можно было включить в обычную роль, хотя
способы оплаты, возвраты, сроки годности и длительность сессий влияют на все
точки аптеки. Личные предпочтения интерфейса при этом хранились только в одном
браузере и не переносились на другое устройство.

Один экран должен обслуживать три разных по владению и риску набора данных. Их
нельзя защищать только скрытием элементов интерфейса или одним общим
разрешением роли.

## Решение

1. Настройки разделяются на три области: личные, локальные для устройства и
   общие для аптеки.
2. Личные предпочтения принадлежат `app_user`, доступны только этому
   пользователю и синхронизируются через сервер. Значения ограничены
   перечислениями и валидированной схемой; произвольные CSS, HTML и JavaScript
   запрещены.
3. Локальные параметры кассы и оборудования хранятся на устройстве в
   пространстве ключей пользователя, аптеки и кассы. Они не содержат токены,
   чеки, персональные данные или другие бизнес-данные.
4. Общие настройки аптеки может читать и изменять только активный владелец из
   защищённого `tenant_ownership`. Это право не является разрешением роли, не
   делегируется сотрудникам и не предоставляется developer, administrator или
   support-сессии.
5. Клиент скрывает недоступные владельцу разделы, но окончательное решение
   всегда принимает backend. Подделанный запрос получает `403`.
6. Сотрудники получают только минимальный рабочий срез параметров, необходимый
   кассе, возвратам и отчётам. Полная модель настроек аптеки им не возвращается.
7. Обновления общих и личных настроек используют номер версии. Запись с
   устаревшей версией отклоняется конфликтом вместо перезаписи более свежих
   изменений.
8. Общие настройки сохраняются только онлайн, явной кнопкой и попадают в
   триггерный audit-log. Личные и локальные визуальные изменения применяются
   сразу и не блокируют работу при слабой сети.
9. `settings.update` выводится из конструктора ролей. Защищённая owner-роль
   может сохранять его только для обратной совместимости, но API не использует
   это разрешение как доказательство владения.

## Последствия

- Каждый пользователь может открыть личные настройки независимо от своей роли.
- Сотрудник с вручную добавленным старым `settings.update` не получает доступ к
  правилам аптеки.
- Платформенная поддержка может восстановить доступ владельца штатным
  процессом, но не может менять настройки от его имени.
- Касса и отчёты продолжают получать необходимые рабочие значения без раскрытия
  панели владельца.
- Настройки оборудования остаются быстрыми и работоспособными без интернета, но
  пользователь должен повторить их на другом устройстве.
- Для будущего Edge-клиента рабочий срез настроек должен входить в версионированный
  bootstrap или отдельный поток конфигурации до включения удалённого изменения
  настроек в production.
