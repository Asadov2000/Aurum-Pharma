# ADR 0016: Поэтапная замена и отзыв ключей узлов синхронизации

- Статус: принято
- Дата: 2026-08-12
- Уточняет: ADR-0002, ADR-0013, ADR-0014

## Контекст

Немедленная замена ключа создаёт опасное окно: если ответ с новым ключом потерян,
рабочее устройство уже не может подключиться старым ключом. Повтор операции также
не должен создавать новый секрет или применять изменённый запрос под тем же
идентификатором. Для узла, который сейчас записывает продажи, замена ключа не может
конкурировать с передачей права записи.

## Решение

Замена выполняется в три этапа:

1. Разработчик с `platform.sync.manage` и недавним MFA создаёт замену, указывает
   основание и точное имя узла. Новый ключ показывается только в первом ответе.
2. Старый ключ продолжает работать. Первое успешное подключение новым ключом
   переводит замену из `pending` в `verified`.
3. После проверки разработчик завершает замену. Новый ключ становится основным,
   а старый атомарно перестаёт работать. До завершения замену можно отменить.

Каждая команда содержит UUID операции, хэш канонического запроса и ожидаемую
версию узла. Повтор с тем же UUID и тем же хэшем возвращает прежний результат без
повторного применения; другой хэш считается конфликтом. Секрет и его хэш не
попадают в административный журнал, audit-log или HTTP-логи.

Отзыв узла является отдельной необратимой командой. Он атомарно меняет статус,
аннулирует текущий ключ и отменяет незавершённую замену. Замена и отзыв запрещены
для активного writer-узла и во время передачи права записи.

Служебные таблицы имеют `tenant_id`, RLS и не доступны `aurum_app`. Прямые
изменения из `aurum_support` также запрещены: запись выполняют только проверяющие
`SECURITY DEFINER` функции. Административный журнал неизменяем.

## Последствия

- Потеря ответа не отключает кассу и не раскрывает секрет при повторе.
- Компрометация старого ключа прекращается только после завершения замены; при
  инциденте следует использовать немедленный отзыв.
- Для writer-узла сначала требуется безопасная передача права записи.
- Будущее усиление канала может добавить mTLS и подпись всего HTTP-запроса, не
  меняя описанный жизненный цикл ключа.
