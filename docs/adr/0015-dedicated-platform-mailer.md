# ADR 0015: Изолированный обработчик платформенных писем

- Статус: принято
- Дата: 2026-08-12

## Контекст

Письмо-приглашение содержит краткоживущий токен активации. Общий Celery worker
имеет доступ к служебной БД, JWT, MFA и данным аптек, поэтому его использование
для SMTP неоправданно расширяет последствия компрометации почтового транспорта.

## Решение

Платформенные приглашения отправляет отдельный процесс `platform-mailer` из
очереди `platform-mailer`. Обычные workers слушают только очередь `default`.

Mailer подключается к PostgreSQL ролью `aurum_mailer` с `NOINHERIT`, без
`BYPASSRLS`, прав владения, временных таблиц и прямого доступа к таблицам. Ему
разрешён только запуск функций получения и завершения доставки. `aurum_support`
может только поставить письмо в outbox. Все три функции выполняются как
`SECURITY DEFINER`, принадлежат `aurum_schema_owner` и имеют фиксированный
`search_path`.

Mailer получает только свой URL PostgreSQL, Redis, SMTP, публичный URL и ключи
шифрования outbox. JWT, MFA, MinIO, метрики и support/app URL ему не передаются.
В production он подключён к внутренней сети данных и отдельной сети для
исходящего SMTP.

## Последствия

Компрометация SMTP-процесса не даёт чтения tenant-данных или выполнения
административных операций. Общий Redis пока остаётся доверенной границей; перед
масштабированием требуется отдельный Redis ACL-пользователь или отдельный broker
для очереди mailer.
