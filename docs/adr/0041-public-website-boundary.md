# ADR-0041: Публичный сайт отдельно от рабочего приложения

- Статус: принято
- Дата: 2026-09-12
- Связано: ADR-0001, ADR-0008, ADR-0033; `docs/implementation-roadmap.md`

## Контекст

По основному домену пользователь должен узнавать о продукте, видеть способы
установки и переходить к общему входу. Рабочее приложение уже существует;
публичная страница не должна раздавать его сессионные данные, менять поведение
кассы или заявлять готовность ещё не выпущенного Windows-клиента.

## Решение

1. Добавить `website/` как отдельный статический сайт: HTML, CSS и локальные
   assets. Сборка, тесты и локальная раздача используют встроенные возможности
   Node. Новых зависимостей или отдельного UI framework в первом блоке нет.
2. Сохранить `frontend/` и `backend/` на текущих местах. Вход, сессия,
   организация, роли и permissions остаются только в рабочем приложении.
   Пользователь с несколькими ролями использует тот же общий вход.
3. В production основной домен обслуживает сайт, поддомен `app` — рабочий UI
   и API через один origin. Публичный сайт переходит по ссылке, а не вызывает
   API и не встраивает приложение в iframe. Расширять CORS или область auth
   cookie ради сайта нельзя; сессионные cookies не распространяются на
   родительский домен и публичный сайт.
4. Адрес входа передаётся build-конфигурацией `APP_URL`. Production-сборка
   требует явный допустимый HTTPS URL и отклоняет localhost/loopback, секреты
   в userinfo, query/hash и недопустимую схему. Конфигурация экранируется при
   выводе в HTML. Dev использует `http://localhost:5173/login`; сайт
   обслуживается отдельно на `http://127.0.0.1:4174`.
   Обратная ссылка «О проекте Aurum Pharma» на странице входа открывает сайт
   в новой вкладке с `noopener noreferrer`, сохраняя незавершённую форму.
   Её адрес задаётся `VITE_PUBLIC_WEBSITE_URL` при сборке frontend. Без настройки
   локальный адрес доступен только при открытии приложения на loopback;
   удалённым пользователям ссылка не показывается до публикации сайта.
   HTTP разрешён только для loopback с локальной страницы; недопустимые адреса,
   userinfo, query/hash отклоняются. Домен сайта не выводится из имени домена
   приложения или параметров входа.
5. Сайт не принимает пароли, аптечные документы или обращения и не хранит
   PII, токены, auth cookies, состояние аптек или стороннюю аналитику. Любой
   будущий сбор данных требует отдельного контракта и проверки.
6. Страница установки различает доступную веб-версию/PWA и будущий Windows
   installer. До выпуска подписанного проверенного артефакта нет кнопки
   скачивания несуществующего файла, вымышленной версии или обещания offline.
   Фактический домен, контакты и тарифы не выдумываются.
7. Установленный Windows-клиент будет открывать рабочий интерфейс по
   Cloud/Edge-архитектуре, а не рекламный сайт. Публичные ссылки не должны
   получать привилегированный desktop bridge.
8. Сборка сайта не читает `.env` рабочего приложения и не требует DB/Redis.
   Результат `website/dist/` — артефакт, не исходник. Публикация сайта,
   приложение и выпуск Windows-пакета — отдельные операции развёртывания.

## Проверки

- Главная и способы установки доступны без входа; переход к приложению
  корректен; назначенный `APP_URL` не подменяется внешним параметром запроса.
- Production build отклоняет отсутствующий/небезопасный адрес, dev работает
  с loopback; данные конфигурации не превращаются в HTML-инъекцию.
- Сайт читается на узком и широком экране; навигация доступна с клавиатуры,
  ссылки различимы, фокус видим, движение учитывает reduced motion.
- Нет запросов к API аптеки, внешних трекеров и фиктивных downloads.
- Изменение проходит PR и обязательный CI gate; локальный сайт не заменяет
  текущий main demo и не меняет его данные.

## Последствия и границы

Публичный сайт может развиваться и публиковаться независимо от кассы. Цена —
отдельная небольшая сборка и необходимость явно задавать адрес приложения.
Общий стиль поддерживается дизайн-правилами и локальными assets; выделение
общей библиотеки компонентов возможно лишь при доказанной необходимости.

Это решение не развёртывает Cloud, не выпускает installer, не включает
offline-auth и не меняет требования writer/fiscal из ADR-0001/0002/0005/0018.
Топология нескольких касс на общем кассовом ПК уточняется отдельным будущим
ADR согласно roadmap.
