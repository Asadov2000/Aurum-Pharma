# ADR-0049: Безопасный выход при потере связи

Статус: принято, 2026-09-27.

## Решение

Нажатие «Выйти» сразу закрывает локальную сессию, очищает закрытые кеши и
инвалидирует уже начатые запросы, включая bootstrap без access-токена. Сетевой
выход выполняется после этого. Неудачный запрос не означает подтверждённый
выход с сервера: на странице входа показано ожидание подтверждения.

Браузер сохраняет только несекретные идентификаторы выхода, подтверждения и
нового явного входа. Access-токен остаётся в памяти, refresh — в httpOnly cookie.
Выход запрещает автоматическое восстановление из cookie после reload, события
online и ответа 401. Подтверждение сервером не снимает этот запрет; его снимает
только успешный новый вход с проверкой учётных данных и дополнительной защиты.

Операции, меняющие refresh-cookie, сериализуются между вкладками одного origin
через Web Locks. Новый вход сначала завершает ожидающий выход под тем же lock.
Поздний ответ старого выхода не отправляется после нового входа. Поздние
результаты refresh, входа и изменения MFA не принимаются после смены локальной
сессии. Между вкладками передаётся только несекретная смена идентификатора,
а доступ и кеши очищаются также при возвращении вкладки в фокус.

Запись нового входа подтверждает только наблюдавшийся идентификатор выхода.
Она не перезаписывает новый запрос выхода другой вкладки. Подтверждение сервера
также хранится отдельно от запроса выхода. Повреждённые или противоречивые
записи запрещают автоматическое восстановление.

## Границы

Механизм рассчитан на актуальный браузер в защищённом контексте (HTTPS либо
локальный loopback) и Windows-клиент с поддержкой Web Locks. Без этой возможности
новый вход после выхода запрещён: ненадёжная блокировка через localStorage
не используется. Настройки браузера, запрещающие постоянное хранение, могут
потребовать смены браузера. Cookie fallback не содержит удостоверения доступа.

Без сети сервер может продолжать считать прежнюю сессию действительной до
подтверждения выхода либо истечения срока. Ручная очистка хранилищ, компрометация
браузера и разные origins находятся вне гарантии синхронизации вкладок. Этот
этап не реализует автономный вход, PIN, блокировку ОС или автономную кассу.

Backend, RLS, правила токенов и пользовательские данные не изменяются.

## Проверки

Unit-проверки охватывают немедленное закрытие доступа, зависший запрос,
устойчивый запрет восстановления, последовательность cookie-операций и поздние
ответы. Браузерные проверки используют настоящие httpOnly cookies: сетевой сбой
с reload, две вкладки, отключение и восстановление сети, повторный явный вход.
Секреты и cookie values не записываются в диагностические артефакты.
