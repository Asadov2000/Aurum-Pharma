# ADR 0032: Исключительное владение кассой одной вкладкой

- Статус: принято
- Дата: 2026-09-04

## Контекст

Серверная идемпотентность защищает от повторной отправки одной и той же команды,
но две вкладки могут независимо создать разные команды для одной кассы. Это
создаёт риск параллельного изменения чека, повторной оплаты или продажи и
неоднозначного восстановления после таймаута.

Web-клиенту нужен один активный владелец рабочего пространства каждой кассы.
Переключение на другую кассу при этом должно оставаться доступным, а закрытие
активной вкладки не должно требовать ручного сброса блокировки.

## Решение

1. Активное рабочее пространство POS монтируется только после получения
   эксклюзивной Web Lock с именем, содержащим идентификатор кассы.
2. Вторая вкладка для той же кассы не запускает восстановление чека, сканер,
   оплату и другие POS-команды. Она показывает понятное состояние «Касса занята»
   и остаётся в очереди на получение блокировки.
3. После закрытия или переключения вкладки-владельца браузер освобождает Web Lock,
   а следующая ожидающая вкладка автоматически получает управление.
4. Выбор другой кассы остаётся доступным в заблокированной вкладке: блокировка
   относится к конкретному `register_id`, а не ко всему приложению.
5. Если Web Locks API отсутствует или возвращает ошибку, POS блокируется безопасно
   и просит обновить браузер. Неатомарная блокировка через `localStorage` не
   используется, потому что две вкладки могут одновременно считать себя
   владельцами.
6. Межвкладочная блокировка является дополнительным барьером. Серверные проверки,
   транзакции, идемпотентность, права и сверка результата остаются обязательными.

## Инварианты

- Для одного `register_id` в одном профиле браузера активна не более одной
  вкладки POS.
- Вкладка без блокировки не выполняет денежные и складские команды.
- Освобождение блокировки не завершает смену и не изменяет чек на сервере.
- Неизвестный результат серверной операции нельзя повторять вслепую после
  передачи управления другой вкладке.

## Следствия

- Поддерживаемый браузер должен реализовывать стандартный Web Locks API.
- Очередь и освобождение блокировки управляются браузером и не зависят от часов,
  таймеров или очистки локального хранилища.
- Блокировка действует внутри одного профиля браузера. Параллельная работа с
  разных устройств отдельно контролируется серверными правилами и будущим
  механизмом владения Edge-устройством.
