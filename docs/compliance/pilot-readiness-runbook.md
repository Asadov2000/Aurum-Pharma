# Проверка готовности пилота Aurum Pharma

- Область: ограниченный web-пилот одной аптеки
- Текущий профиль: `LOCAL_DEMO`
- Текущее решение: `blocked`
- Дата ревизии: 2026-09-04

Этот runbook не является юридическим заключением. Он не позволяет разработчику
самостоятельно объявить продукт законным или безопасным для реальных продаж.
Его задача — не дать потерять обязательный пункт и связать решение с проверяемым
доказательством.

## Источники состояния

- `pilot-legal-gate.md` объясняет обязательные юридические и эксплуатационные условия.
- `pilot-readiness-policy.json` фиксирует полный обязательный перечень и запрещает
  ослаблять его через manifest.
- `pilot-readiness-manifest.json` хранит текущее машиночитаемое состояние.
- `tajikistan-legal-register.md` связывает нормы с решениями Aurum.
- Подписанные документы, секреты и персональные данные находятся только во
  внешнем защищённом evidence-хранилище.

Статусы manifest:

| Статус | Значение |
|---|---|
| `verified` | Контроль проверен и имеет доказательство |
| `pending` | Обязательное действие или подтверждение ещё не получено |
| `disabled` | Рискованная функция технически выключена и это доказано тестом |
| `not-applicable` | Неприменимость зафиксирована для необязательного gate; обязательный gate остаётся блокером |

`disabled` допустим только для функции, которую безопасно исключить из пилота.
Им нельзя закрыть регистрацию компании, защиту данных, разрешение аптеки,
инфраструктурную безопасность или подпись протокола допуска.

Поле `verification` не позволяет закрыть внешний вопрос ссылкой на тест в Git:
`repository` требует файл проекта, `external` — идентификатор защищённого
доказательства, а `hybrid` требует оба вида.

При решении `approved` валидатор дополнительно требует полный Git commit,
идентификатор зелёного CI, срок действия, digest образов backend/gateway/recovery
и пять внешних подтверждений. Commit обязан совпадать с проверяемым `HEAD`.

## Команды

Проверить структуру manifest и существование repository-доказательств:

```powershell
./scripts/Test-PilotReadiness.ps1 -Mode Validate
```

Проверить возможность реального запуска:

```powershell
./scripts/Test-PilotReadiness.ps1 -Mode Enforce
```

`Validate` используется в CI и подтверждает только честность реестра. `Enforce`
сейчас обязан вернуть ненулевой код, потому что реальный пилот не разрешён.

## Как закрывается внешний gate

1. Ответственный получает подписанный документ, официальный ответ или протокол проверки.
2. Документ проверяет указанный в gate владелец и, где требуется, лицензированный юрист РТ.
3. Файл помещается в защищённое неизменяемое хранилище; в Git записывается только
   непрозрачный идентификатор `evidence://<система>/<id>/<версия>`.
4. В manifest меняются статус и evidence в отдельном pull request.
5. CI проверяет manifest, код и тесты. Изменение принимает независимый reviewer.

Ссылка `evidence://` не является доказательством сама по себе. Перед подписью
протокола допуска пять владельцев обязаны открыть соответствующий объект,
проверить подпись, срок действия, область и связь с release commit.

## Процедура допуска

1. Зафиксировать release commit и запретить попутные изменения.
2. Получить зелёный обязательный CI gate и сохранить его run ID.
3. Выполнить staging deployment с production-подобной конфигурацией.
4. Провести независимый pentest и закрыть critical/high находки.
5. Восстановить систему из внешней WORM-копии и зафиксировать измеренные RPO/RTO.
6. Провести рабочий день: открытие смены, продажа, потеря ответа, сверка,
   возврат, закрытие смены, отчёты и аварийное восстановление.
7. Проверить документы аптеки, фискальный и платёжный контуры выбранного профиля.
8. Запустить `Test-PilotReadiness.ps1 -Mode Enforce`.
9. Подписать версионированный протокол с commit, образами, конфигурацией,
   документами, известными рисками и сроком действия допуска.

## Автоматический отзыв

Решение возвращается в `blocked`, если меняется закон, hosting/юрисдикция,
платёжный или фискальный провайдер, критический поток продажи, схема персональных
данных, release commit после приёмки либо подтверждается серьёзный инцидент.
Повторный запуск требует нового manifest и подписанного протокола.
