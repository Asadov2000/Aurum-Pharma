# Публичный сайт Aurum Pharma

Независимый статический сайт: описание продукта, варианты установки и ссылка на
единый вход. Рабочее React-приложение остаётся в `../frontend/`. Здесь нет API,
форм входа, токенов, аналитики, service worker или клиентских данных. Новый
фреймворк и npm-зависимости не требуются: сборка использует встроенные API Node 24.

## Локальный просмотр

Из корня репозитория:

```powershell
node website/scripts/build.mjs
node website/scripts/serve.mjs
```

Открыть <http://127.0.0.1:4174>. Ссылка «Войти» ведёт на существующее приложение
<http://localhost:5173/login>. Preview слушает только loopback и предназначен
только для разработки. Рабочий demo launcher и БД ему не нужны.

## Production-сборка

```powershell
$env:APP_URL = 'https://app.example.test/login' # заменить реальным адресом приложения
node website/scripts/build.mjs --production
Remove-Item Env:APP_URL
```

Сборка требует явный HTTPS-адрес приложения, запрещает credentials, query и
fragment. Файлы результата находятся в `website/dist/`; они не коммитятся.
Примерный домен выше не является адресом работающего Aurum. Публикация возможна
после выбора домена и подготовки сервера. Изменение APP_URL требует новой сборки.

Публичный домен отдаёт **только** содержимое dist, `app`-поддомен — существующее
приложение и его API с одного origin. Не расширять область auth-cookie на
публичный домен. Production-раздача — через предусмотренный Caddy/TLS с CSP,
`nosniff`, `Referrer-Policy` и без SPA fallback для отсутствующих установщиков.
Node preview не является production-сервером. Точные маршруты развёртывания
будут добавлены вместе с целевым сервером; текущий gateway не изменён.

## Проверки

```powershell
node website/scripts/test.mjs
node website/scripts/check-browser.mjs
```

Browser check использует уже закреплённый `@playwright/test` из frontend, без
отдельной копии зависимостей. Нужны подготовленный `frontend/node_modules` и
Chromium текущей версии Playwright. Их установка — обычная подготовка среды из
`docs/e2e.md`, а не автоматическое действие этих скриптов. Для уже установленного
WebKit можно дополнительно задать `WEBSITE_BROWSERS=chromium,webkit`.

Проверяются конфигурация ссылки входа, обе страницы, ресурсы и ссылки, запрет
API/файлов вне dist, клавиатура, переходы и ширины 320/390/768/1440 px. Скриншоты
и временные сборки остаются в игнорируемой `.codex/`, отдельно от рабочей БД.
Эмуляция мобильного браузера не заменяет проверку на настоящем iPhone.

## Карта

- `src/index.html` — главная страница.
- `src/downloads/index.html` — установка и честные статусы доступности.
- `src/assets/` — локальные стили и изображения без клиентских данных.
- `scripts/` — сборка, локальный preview и проверки.
- `tests/` — тесты сборки и HTTP-поведения preview.
- `dist/` — готовый статический результат.

Windows-установщик и автономный POS не входят в этот блок. До появления
подписанного релиза страница не должна предлагать фиктивное скачивание. Релизные
бинарные файлы, ключи подписи и рабочие базы никогда не попадают в `src/` или Git.
